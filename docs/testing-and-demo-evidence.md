# Testing and Demo Evidence Checklist

This checklist defines the evidence needed to close Sprint 6 testing and demo tasks without unsupported claims.

## Demo Evidence Required

Capture still screenshots or video frames for the following states:

- Start page
- Onboarding or registration flow
- Week 1 campus map
- Active/inactive location marker behaviour
- Yuki event introduction
- Yuki choice screen
- Treasure-found outcome
- Missed-opportunity or hint outcome, if available

Each screenshot should show only relevant product UI and should avoid unrelated browser/account/private details.

## External Testing Evidence Required

Record a compact testing summary with:

- participant count
- date or week of testing
- test device or environment
- task flow used by testers
- key observations about onboarding clarity
- key observations about map/event understanding
- UI readability findings
- bugs or blockers
- follow-up Jira issues created

## Evidence Handling Standard

- Evidence should be embedded directly into the final Sprint 6 DOCX, not replaced by external links.
- Jira issues may be moved to Done only when the evidence exists or a clear completion note explains the evidence source.
- If participant no-shows or limited testing occurred, document that honestly as a testing constraint and reflection item.

## Current Status

The repository and Jira contain the testing plan and review structure. Final participant results and product screenshots require team-provided material before the final evidence-closed DOCX is submitted.
