# ANU TreasureMap — Sprint 5 Risk and Dependency Log

## R1. Post-pivot gameplay alignment risk
**Description:** After the Sprint 4 concept pivot, the intended core gameplay loop was not yet shared clearly across design, UI, and implementation work.  
**Impact:** Main playable-flow implementation could not progress confidently in parallel across streams.  
**Mitigation in Sprint 5:** The team used an HCI paper prototype to expose alignment gaps, clarified a tutorial-first slice, converted stakeholder feedback into Jira actions, and prioritised rule and flow simplification.  
**End-of-sprint status:** Reduced for the tutorial flow, but still open for the full main gameplay loop.

## R2. Sprint scope risk
**Description:** The original Sprint 5 goal (playable demo + internal testing) was too broad while the post-pivot gameplay logic was still being clarified.  
**Impact:** Risk of fragmented progress across multiple workstreams and weak integration by the end of the sprint.  
**Mitigation in Sprint 5:** The team protected tutorial flow, menu/UI shell, paper prototype, and feedback-tracking as the main end-of-sprint deliverables, while deferring broader event integration and dynamic asset loading.  
**End-of-sprint status:** Tutorial-first scope stabilised; full gameplay integration moved to the next sprint.

## D1. Core-loop dependency
Main gameplay implementation depended on a locked rule set and a simplified node/event structure.

## D2. UI/content dependency
UI, assets, and encounter presentation depended on a shared tutorial flow and an agreed playable-slice scope.

## Carry-over to next sprint
- Lock the main gameplay loop
- Finalise the simplified node/event set
- Deepen implementation and structured testing
